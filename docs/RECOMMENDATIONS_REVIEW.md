# Review of Gemini recommendations — 2026-10-11

Scope: compare the supplied recommendations with the prepared standalone repository and selected private source exports. This is a targeted source/documentation review, not a new functional certification or deployment. No workflow, credential, database, frontend code or payment is changed.

| Item | Applicability | Evidence class and finding |
| --- | --- | --- |
| Installation and English submission materials | APPLICABLE to submission | Official rules permit complete repository setup instructions or hosted access; judges may choose not to test. Neither a one-click installation requirement nor an automatic presentation penalty is specified. English materials or translations are required. Current setup remains multi-step and needs provider configuration. |
| Workflow 12 legacy DocuBridge handler | NON APPLICABLE to standalone engine; APPLICABLE to source selection | STATIC_ANALYSIS: the private export contains the listed legacy variables, tables, alert wording and credential label. It is excluded from this repository. Engine 13's local `settings.errorWorkflow` is empty; the portable export uses neutral credential names. Renaming unrelated database tables/credentials is not warranted. |
| PayPal origin/ports | APPLICABLE | STATIC_ANALYSIS: both return and cancellation URLs in Stage 1 fall back to 3006 when `dbCtx.public_origin` is empty. The default app port is 3005. `setup.cjs` writes the explicit validated `PAYFLOW_PUBLIC_ORIGIN` into `payflow_config.public_origin`; `.env.example` sets 3005 and the launch wrapper uses the same origin. Repeat setup refuses conflicting database configuration. Manual installs that omit configuration remain exposed to this fallback mismatch. No broken redirect was reproduced in this review. |
| Filesystem operator sessions | APPLICABLE to deployment documentation | STATIC_ANALYSIS: `operator-auth.ts` writes and reads sessions beside the configured operator file. The README already limited deployment to a local single instance with persistent filesystem sessions. Clarified host Node.js execution, persistent writable private directory, unsupported serverless/ephemeral storage, and that the supplied Compose volumes do not cover the host cockpit. |
| Deployed n8n state | APPLICABLE only to claims about the current instance | NOT_VERIFIED in this review: read-only API requests for the two selected workflow identities could not reach the configured instance. Local exports are not presented as current deployment proof. |
| New provider/payment execution, hosted deployment, concurrency or full regression audit | NON APPLICABLE to this documentation delta | No runtime/business code change. Existing evidence remains documented in PREPARATION.md; no new provider or end-to-end PASS is claimed. |

Outcome: the handler finding is real in the old private export but absent from the submission candidate. The port mismatch is a genuine fallback limitation already avoided by the supported bootstrap, not a demonstrated failure of that installation. Filesystem persistence is a real deployment constraint, now more explicit. Hosted judge access and English/translated submission materials remain submission work; nothing is published by this review.
